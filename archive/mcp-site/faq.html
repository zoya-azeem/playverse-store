Function calling is a model capability: the model emits a structured request to invoke a function you described to it. MCP is an application protocol that standardises where those descriptions come from, how they are discovered at runtime, and how results come back — plus resources and prompts, which function calling has no concept of.

Security and operations

Treat it exactly like any other dependency you are about to give filesystem access to. A stdio server runs as a local process with your user's privileges, so it can read what you can read. Read the source, pin an exact version rather than a floating tag, prefer inspectable code over opaque binaries, and scope what you hand it — a directory, not your home folder.

No. A server sees the arguments of calls made to it, and nothing else. It cannot read the conversation, the system prompt, or traffic to other servers — each server gets its own isolated client session. The exception is deliberate: if a server requests sampling, the client decides what context, if any, to include in that completion.

This is the real risk, and it is not fully solved by anything in the protocol. A fetched page or a database row can contain text engineered to read as an instruction. Mitigations that help: treat all tool output as untrusted data and frame it that way in context, require human approval for side-effecting calls, never let one tool's output authorise another tool's call, and apply least privilege so a successful injection has little to reach.

The protocol and SDKs are free and open source. What costs money is tokens: tool definitions occupy context on every request, and tool results occupy more. A server with thirty verbose tools has a real per-call price. Keeping descriptions tight and results summarised is a cost control as much as a quality one.

In order: validate the config JSON; use an absolute path to the interpreter, since the client does not inherit your shell's PATH; check that nothing writes to stdout; then run the server under the Inspector to isolate the server from the client. Full troubleshooting table.

Versions are negotiated during initialize, so a client and server agree on a version they both support rather than guessing. The protocol has evolved — the two-endpoint HTTP+SSE transport gave way to Streamable HTTP, for instance — so pin your SDK version, read release notes before upgrading, and keep an eye on which revision your target clients actually speak.

Twenty minutes connecting the filesystem server to a client you already use, twenty writing a one-tool server that wraps an API you know, and twenty in the Inspector deliberately breaking it to see what the errors look like. That hour teaches more than reading the specification front to back.
