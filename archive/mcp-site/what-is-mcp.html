What is the Model Context Protocol?

An open standard for connecting AI applications to the systems where context actually lives. Think of it as a common port: one shape of plug, many devices.

The short version

MCP defines how an AI application asks an external system for context and for permission to act on it. The application and the system do not need to know anything about each other's internals — only the protocol.

Concretely, it is a JSON-RPC 2.0 message layer with a defined handshake, a fixed vocabulary of request types, and a small set of primitives that a server can expose. It is transport-agnostic: the same messages run over a local pipe or over HTTP.

One sentence to remember: MCP is to AI context what a device driver interface is to hardware — the host does not care who wrote the server, only that it answers the agreed messages.

The problem it solves

Language models are trained once and then frozen. Anything specific to you — this week's sales figures, your team's naming conventions, the ticket you filed an hour ago — is simply absent. You can paste it in by hand, but that does not scale and it does not let the model act.

The obvious fix is to build integrations. The trouble is the arithmetic. Each AI application needs its own connector for each data source, in that application's own plugin format:

ApproachIntegrations to buildAdding a 6th data sourceAdding a 5th app
Bespoke glue
4 apps × 5 sources		 20 +4 new connectors +5 new connectors
MCP
4 clients + 5 servers		 9 +1 server, works everywhere +1 client, gets all servers

That is the whole value proposition. MCP converts a multiplication into an addition. A server you write for your warehouse works in a desktop chat app, an IDE and your own internal agent without modification.

The three server primitives

A server declares which of these it supports during the handshake. Most servers implement tools; resources and prompts are optional but valuable.

⚙

Tools

Model-controlled. The model decides when to call them.

Each tool has a name, a description and a JSON Schema for its input. The description is a prompt: write it for a reader who has never seen your system.

📄

Resources

Application-controlled. The host chooses what to attach.

Addressed by URI, returned as text or binary. Can be listed, read, subscribed to for change notifications, or templated with parameters.

💬

Prompts

User-controlled. A person picks them deliberately.

Named templates with typed arguments that expand into a prepared message sequence. Usually surfaced in the UI as slash commands.

Why the distinction matters. The three categories encode who is in control. That is a security boundary, not a stylistic choice: a host can reasonably auto-attach a resource, but it should always ask before running a tool that writes somewhere.

And three the other way

The protocol is bidirectional. A client can declare capabilities that servers may call back into:

  • Sampling — the server asks the client to run a model completion on its behalf, so server authors do not need their own API key or model choice.
  • Roots — the client tells the server which directories or URIs are in scope for this session.
  • Elicitation — the server asks the user a structured question mid-operation, rather than failing on a missing argument.

How is this different from function calling?

Function calling is a model feature: the model emits a structured request to invoke a function you described. MCP is an application protocol: it standardises where those function descriptions come from, how they are discovered at runtime, and how results travel back. The two are complements, not competitors — a host typically uses function calling to let the model choose, and MCP to source the choices.

Who should care

If you build AI applications

Implement the client side once and inherit the whole server ecosystem. You stop writing integrations and start choosing them.

If you own a data source or API

Write one server and become reachable from every MCP-capable assistant, without partnering with each vendor individually.

If you run a platform team

Expose internal systems through servers you host and audit. Access policy lives in your code, not in a prompt.

If you are just curious

A reference server plus a config file is a fifteen-minute experiment. The quickstart is the fastest route in.

Glossary

TermMeaning
HostThe AI application a person interacts with. Owns the model, the UI and the approval decisions.
ClientThe connector inside the host that maintains one session with one server. Hosts run several in parallel.
ServerA program exposing tools, resources and prompts over the protocol. Local process or remote service.
CapabilityA feature declared during initialisation. Neither side may use a feature the other did not declare.
TransportHow bytes move: stdio for local processes, Streamable HTTP for remote ones.
JSON-RPC 2.0The message format: requests with an id, matching responses, and one-way notifications.
SamplingA server asking the client to perform a model completion for it.
RootA directory or URI the client declares as in-scope for the session.
ElicitationA server requesting structured input from the user mid-operation.
InspectorThe developer tool for exercising a server by hand, with no model involved.
