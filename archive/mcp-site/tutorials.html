Tutorials

Twelve walkthroughs in a deliberate order. Each one ends with something that runs, and each builds on the one before it.

The path

Beginner

Get something working

Connect a reference server, write your first tool, learn to debug with the Inspector. No protocol internals required.

Intermediate

Make it genuinely useful

Real data sources, resources and prompts, error handling that the model can recover from, tool descriptions that actually get used.

Advanced

Ship it to other people

Remote transport, OAuth, multi-tenant sessions, the client side of the protocol, and testing an agent loop end to end.

Beginner

Beginner15 minPython

Your first tool in 15 minutes

Install the SDK, define a single tool with a typed argument, run it over stdio and call it from a client. The shortest complete path from nothing to working.

Covers: FastMCP, stdio, client config

Beginner20 minTypeScript

The same server in TypeScript

The Node equivalent, with Zod schemas for validation and a brief detour into why the SDK wants your tool handler to return content blocks rather than plain strings.

Covers: TS SDK, Zod, content blocks

Beginner25 minTooling

Debugging with the Inspector

Drive your server by hand with no model in the loop. Learn to read the raw JSON-RPC traffic so you can tell a broken handler from a badly described tool.

Covers: Inspector, JSON-RPC frames, stderr logging

Beginner20 minConcepts

Exposing files as resources

Add read-only context addressed by URI, including templated resources with parameters, and see why resources are the host's decision rather than the model's.

Covers: resources/list, resources/read, URI templates

Intermediate

Intermediate45 minPython

A read-only database server

Expose table schemas as resources and a parameterised query tool. Includes statement allow-listing, row limits and result summarisation so a wide table cannot flood the context window.

Covers: SQL safety, pagination, schema resources

Intermediate30 minCraft

Writing tool descriptions the model will use

The highest-leverage work in server design. A before-and-after rewrite of four weak descriptions, with a repeatable method for testing whether a change actually helped.

Covers: naming, when-to-use guidance, schema descriptions

Intermediate35 minConcepts

Prompts as reusable workflows

Package a code-review checklist and an incident postmortem into prompt templates with typed arguments, and see how clients surface them as slash commands.

Covers: prompts/list, prompts/get, argument completion

Intermediate40 minReliability

Errors a model can recover from

The difference between a protocol error and a tool error, why that distinction decides whether the agent can retry, plus timeouts, partial results and progress notifications.

Covers: isError, JSON-RPC errors, progress tokens

Advanced

Advanced60 minDeployment

From stdio to Streamable HTTP

Take a working local server remote: the single-endpoint design, session identifiers, when to upgrade a response to an SSE stream, and how to keep sessions alive behind a load balancer.

Covers: Streamable HTTP, Mcp-Session-Id, SSE

Advanced75 minSecurity

OAuth 2.1 for a public server

Protected resource metadata, dynamic client registration, token audience validation, and a close look at the confused-deputy mistake that makes a server a credential laundering service.

Covers: OAuth 2.1, audience checks, scope design

Advanced50 minClient side

Writing an MCP client

Implement the other half: the handshake, capability tracking, running several sessions in parallel, and turning discovered tools into function definitions for a model call.

Covers: initialize, capability negotiation, session management

Advanced45 minAdvanced

Sampling and elicitation

Let your server borrow the host's model instead of carrying its own API key, and ask the user a structured question mid-operation rather than failing on a missing argument.

Covers: sampling/createMessage, elicitation/create, human approval

Advanced55 minTesting

Testing an agent loop end to end

Fixtures for protocol conformance, a fake client for integration tests, and evaluation runs that check whether the model actually picks the right tool for a given request.

Covers: conformance tests, fakes, tool-selection evals

Advanced40 minOperations

Running servers in production

Containerising a server, dropping privileges, structured logging that never touches stdout, health checks, rate limits per session and an audit trail of every tool call.

Covers: containers, observability, rate limiting, auditing

How to work through these. Do the first beginner tutorial even if it looks trivial — it establishes the config and debugging loop every later one assumes. After that, skip freely: the intermediate and advanced tracks are independent of each other.
